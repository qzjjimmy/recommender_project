# 项目三演示与验收用例

## 10 分钟演示顺序

1. 打开 `/health`，确认推荐、索引和多模态状态。
2. 文字输入“50元以内 收纳用品”，说明品类和预算硬约束先于排序。
3. 语音输入同一需求，展示转写文本、推荐结果和统一 trace。
4. 上传家电图片，展示场景、物体、类目和可编辑建议查询，再执行推荐。
5. 对结果点赞，展示同一查询的分数变化；再在新会话搜索，确认旧会话点踩不污染。
6. 点击一行记录继续浏览，打开 `/api/session/context` 展示短期偏好。
7. 停止桥接服务后上传图片，展示 503 降级提示，并继续完成文字搜索。
8. 打开 `outputs/stage06_acceptance.json`，说明三类输入和提交包审计结果。

## 正常与边界样例

| 类型 | 输入 | 期望 |
|---|---|---|
| 正常 | 50元以内 收纳用品 | 价格和品类硬约束全部满足 |
| 正常 | 图片中有冰箱 | 返回家用电器视觉线索与推荐 |
| 正常 | 对首条结果点赞 | 分数上升，解释引用反馈来源 |
| 缺槽位 | 找类似的商品 | 追问目标商品，不猜测商品 ID |
| 冲突 | 先“手机”再“家用电器” | 提示品类冲突 |
| 低置信度 | 视觉标签置信度 0.3 | 标签被忽略 |
| 空结果 | 100元以内 家用电器 | 返回明确无结果提示 |
| 故障 | 桥接不可达时上传图片 | 503、text-only 降级、文字仍可用 |

## 答辩要点

- 两项目通过 HTTP 协作，不直接读取内部对象。
- `trace_id` 从 Flask 经桥接服务返回，失败分支也保留同一 trace。
- 推荐解释只使用 EvidencePack，不用通用模板补造事实。
- 点赞可持久化，点踩和浏览仅在当前会话生效。
- 多模态模型不可用时保留可离线运行的文字规则链路。
